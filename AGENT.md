## Маршрутизация задач

### → Local (Ollama, бесплатно) — по умолчанию
- Рутинные правки по готовому примеру
- Добавление тестов к существующим функциям
- Документация, комментарии, переименование
- Небольшие скрипты и утилиты
- Любая задача без признаков сложности

### → DeepSeek flash (проверка, дёшево)
- Верификация результата Ollama (`--verify`)
- Задача, с которой Ollama не справилась с первой попытки

### → DeepSeek v4-pro (сложное, дороже)
- Новые модули со сложной логикой
- Задачи, затрагивающие несколько файлов сразу
- Вторая неудачная попытка Ollama
- Ключевые слова: `архитектур`, `рефактор`, `новый модуль`, `совместимост`, `интерфейс`, `не работает`, `ошибка непонятна`

### → Antigravity (диспетчер, только он)
- Архитектурные решения: структура модулей, интерфейсы, форматы данных
- Любое изменение, ломающее совместимость
- Расследование неясных ошибок
- Если DeepSeek тоже не справился

## Использование dispatcher.py

```bash
# Авто-маршрут (рутина → Ollama, сложное → DeepSeek)
python3 dispatcher.py "задача"

# Ollama делает, DeepSeek проверяет
python3 dispatcher.py "задача" --verify

# Принудительно в Ollama
python3 dispatcher.py "задача" --ollama

# Принудительно в DeepSeek
python3 dispatcher.py "задача" --deepseek

# DeepSeek v4-pro (максимум)
python3 dispatcher.py "задача" --strong
```

## Правила для всех

1. Перед задачей прочитать этот файл и карту модулей проекта.
2. Не менять архитектуру и публичные интерфейсы без явной команды.
3. Одна задача — один коммит. Всегда коммитить перед серьёзной правкой агента, чтобы можно было откатиться.
4. После правки запустить тесты. Если тестов на это место нет — сначала добавить.
5. В коммит-сообщении или в шапке файла указывать, какая модель что делала.
6. Никогда не включать секреты и ключи в код или в запросы.

## Эскалация

- Ollama не справилась дважды → передать в DeepSeek flash
- DeepSeek flash не справился → передать в DeepSeek v4-pro
- DeepSeek v4-pro не справился или задача архитектурная → возврат к Antigravity
- Не знаешь кому → вверх, не вниз

## Карта модулей проекта

> Заполнить: короткое описание каждого модуля.

- `boardcam/` — основная библиотека CAM
  - `cam/` — генерация G-кода (карманы, профиль, вкладки)
  - `design/` — модель изделия, загрузка из mesh
  - `geometry/` — полилинии, офсеты, расстояния
  - `jobs/` — job-файлы, листы, пакеты
  - `scad/` — работа с OpenSCAD (echo, runner, svg, stl)
  - `selection/` — правила выбора заготовок
  - `verify/` — аналитика, heightmap, lint, отчёты
  - `post/` — постпроцессор (Masso)
  - `preview/` — топ-вид
- `dispatcher.py` — маршрутизатор задач между моделями
- `tune_pipeline.py` — тюнинг pipeline
- `tests/` — тесты
- `data/` — machine.json, materials.json, tools.json
- `out/` — результаты работы (NC, SVG, отчёты, кэш)
- `shapes/` — SCAD-формы (leaf, pinwheel, tray)
