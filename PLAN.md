# План: раскладки + UI (договорено 2026-09-20, старт — следующая неделя)

Цель: выбирать дизайн менажницы и параметры в UI → на выходе G-code.
Референс: круглая доска, 5 отсеков «вертушкой» + центральный карман (фото прислано в чате).

## Решения (приняты пользователем, не переобсуждать)

1. **Первая версия — только круглый наружный контур.** N отсеков + центральный,
   прямые и спиральные стенки, 3–8 секторов. Ромашка / восьмиугольник / форма
   с ручкой — отложены (это +день: наружный контур зашит в 8 местах и ломает
   трюк с переворотом квадратной заготовки).
2. **Кнопка «Сгенерировать» — блокирующая** + мемоизация растра. Без фоновых
   задач и прогресс-баров.
3. **Зависимости не добавляем.** shapely/pyclipper не нужны: объединение
   окружностей (для отложенной ромашки) считается аналитически дугами.

## Что НЕ делаем без отдельной просьбы

Экспорт DXF/AI/CDR/PDF. Фотореалистичный 3D-рендер (превью остаётся плоским SVG
сверху). Скругление наружной кромки — физически невозможно имеющимся набором фрез.

## Этап 1. Движок форм (~1 ч)

Все ссылки — `generate_board.py` в этом каталоге.

| где | что менять |
|---|---|
| `spiral_edge:216` | `base = i * math.radians(120.0)` → `i * 360.0 / N_POCKETS` |
| `build_pockets:436-438` | `range(3)` → `range(N_POCKETS)`; новая константа `N_POCKETS = 5` |
| `Pocket` (`:258`) | добавить `from_poly(pts)` — конструктор из готового полигона мимо спиральной математики. Выставить те же поля: `poly / area / sign / r_min / mid / _grid / _cell`. Даёт центральный карман |
| `Pocket.raster:418` | **баг**: `rmin = max(2.5, self.r_min - Rt)`. Для кармана, накрывающего центр, `r_min` = его собственный радиус → полярный растр выродится в одну дугу по краю, середина останется нетронутой. Нужно `0.0 if point_inside((0,0), self.poly)` |
| `spiral_edge:215` | `k = log(R_p/r_h)/delta` → деление на ноль при `SPIRAL_SWEEP=0`. Нужна ветка для прямой радиальной стенки (сектора 4/5/6/8 с картинки-каталога) |
| новое | `LAYOUTS = {...}` — раскладка как функция, возвращающая список полигонов. Фото = «вертушка-5 + центр» |
| косметика | тексты «3 compartments» / «3 отсека» в `op_rough:811` и отчёте; `HUB_R` меняет смысл на «радиус центрального кармана + WALL_W» |

Проверить после: при 5 отсеках стенки у центра сходятся плотнее. Уже сейчас при 3
отсеках фрезе D19 недоступно **74 из 515** точек чистового обхода. Смотреть в
`report.txt` разделы КОНТРОЛЬ ЗАЗОРОВ и КОНТРОЛЬ ПОКРЫТИЯ. Лечится увеличением
радиуса центрального кармана.

## Этап 2. Фрезы как данные (~1 ч)

Сейчас `TOOL_EM / TOOL_PROFILE / TOOL_BOWL / TOOL_SURF` (`:74-105`) — четыре
глобальных dict, намертво привязанных к операциям (`op_rough`→EM, `op_finish`→BOWL,
`op_profile`→PROFILE). Для выбора фрезы в UI:

* список `BITS` с полем `role` (черновая / чашечная / контурная / торцовочная)
  и `note` — что фреза делает человеческими словами;
* операция берёт фрезу по роли;
* свою фрезу можно добавить, не трогая код.

Эндпоинты JSON: `/bits`, `/woods`, `/layouts` — UI строит списки сам, без дублей в HTML.

## Этап 3. UI (~2 ч)

`serve.py` (76 строк) + `interactive.html` (10 ползунков, живое SVG-превью,
кнопка генерации, показывает report.txt).

* **Галерея раскладок** — плитки, каждая рендерится тем же `shape_svg` (`:1048`)
  с параметром layout. Клик = выбор.
* **Порода** — выпадающий список из `WOODS` (`:111`, 9 пород). Уже считаются
  множитель подач, обороты и положение регулятора Makita (`dial_for:541`) —
  просто вывести в UI.
* **Фрезы** — чекбоксы. Выбрал → её траектории своим цветом + строка: диаметр,
  обороты, подача, глубина за проход, машинное время, что снимает. Все галки =
  сводная картина + суммарное время.
  **Механика почти готова**: пути уже помечены тегами `rough / finish / profile`
  (`main:1327-1338`), `svg_preview:1027` красит по тегу. Нужен фильтр + тег per-bit.
* Кнопка «Сгенерировать» — как сейчас.

## Замеры (сделаны 2026-09-20, macOS, python3.14)

Полный прогон `generate_board.py` — **51 с**, итог `ГЕОМЕТРИЯ И ТРАЕКТОРИИ В ПОРЯДКЕ`,
линтер по всем 4 файлам чистый.

```
build_pockets      0.00 с
raster (1 карман)  0.68 с
contour_runs       0.22 с
op_rough           3.96 с
coverage (1 карман) 1.53 с   × 6 вызовов
```

Растр считается заново трижды за прогон (операции, отчёт, превью) — мемоизация по
`(tool, allow, stepover)` срежет примерно треть.

Отсюда деление в UI: форма — мгновенно; траектории выбранной фрезы — 4–5 с;
полные проверки + G-code — минута по кнопке.
